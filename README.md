# 商品比較・ランキングアプリ（ペアワイズ比較）

複数の商品候補から、1対1の比較（ペアワイズ比較）を繰り返して優先順位・ランキングを算出するWebアプリです。
外部サーバーやビルドツールを一切使わず、HTML / CSS / JavaScript のみで動作します。

## ファイル構成

- `index.html` : 画面構造（比較・ランキング・商品管理・バックアップ）
- `style.css` : PC・iPhone両対応のレスポンシブスタイル
- `ranking.js` : Bradley-Terryモデルによるランキング計算・次のペア選択アルゴリズム
- `app.js` : UI操作・`localStorage` 保存・JSONエクスポート/インポート
- `README.md` : セットアップおよびiPhoneでの利用手順

---

## PC（Windows + VS Code）での開発・プレビュー方法

1. フォルダを VS Code で開きます。
2. 拡張機能 **Live Server**（Ritwick Dey作）をインストールしている場合、`index.html` を右クリックして **「Open with Live Server」** を選択します。
   - Live Server がない場合でも、`index.html` を Chrome や Edge にドラッグ＆ドロップするだけでそのまま動作します（外部モジュール通信や `fetch` を使っていないため `file://` でもCORSエラーになりません）。
3. 「商品管理」タブの「サンプル10件を追加」ボタンを押すと、すぐに10商品の比較テストができます。

## iPhone単体での導入・オフライン利用方法

インターネット公開やPCの常時起動なしで、iPhone単体でオフライン利用する方法は以下の2通りがあります。

### 方法A：iPhone用ローカルWebサーバー／HTMLプレビューアプリを使う（推奨・最も確実）

iOSの標準「ファイル」アプリから `index.html` を直接開く場合、iOSのセキュリティ仕様（QuickLookプレビュー）により、**外部の `style.css` や `ranking.js` が読み込まれない・画面を閉じると `localStorage` が初期化される** といった制約が発生します。

そのため、iPhone単体で確実に `localStorage` の永続化とオフライン動作を行うには、以下のいずれかの方法をとります。

1. **ローカルWebサーバー／エディタ系アプリ（無料あり）を利用する手順**
   - App Store で「**Koder Code Editor**」「**Documents by Readdle**」「**Web Server**（ローカルHTTPサーバーアプリ）」などのローカルHTML実行・プレビュー対応アプリをiPhoneにインストールします。
   - Windows PCから iCloud Drive / Google Drive / USBケーブル（iTunes・Appleデバイスアプリ）経由で本フォルダ一式をiPhoneの「ファイル」アプリ内にコピーします。
   - アプリ内でフォルダを開き、`index.html` をプレビュー（またはローカルホスト起動してSafariで開く）ことで、CSS/JSの読み込みおよび `localStorage` への永続保存が正常に機能します。

### 方法B：1ファイル版HTMLとしてSafariのホーム画面に追加する（単一ファイル運用）

外部サーバーアプリすら入れず **iPhone標準のSafariだけ** で完結させたい場合は、HTML/CSS/JSを1つの `.html` ファイルに結合した単一ファイルを用意し、Data URL またはローカルHTTP経由で一度Safariに開かせて「ホーム画面に追加」する方法があります。ただし、iOS Safariの仕様として **7日間サイトにアクセスしないとスクリプトで書き込んだ `localStorage` が自動削除される（ITPの7日ルール）** 制限があります。

> **重要（データ保全の運用）**: iOSのストレージ自動クリーンアップや7日ルールによるデータ消失を防ぐため、本アプリの「履歴・保存」タブにある **「JSONをダウンロード」または「JSONをクリップボードにコピー」** を使って、iPhoneの「ファイル」アプリや「メモ」アプリに定期的にバックアップを残す運用を推奨します。

## ランキングアルゴリズム（Bradley-Terryモデル）について

- **採用理由**: 単純な勝率では対戦相手の強さが考慮されず、Eloレーティングでは比較する順番によって最終順位が変わってしまいます。Bradley-Terryモデルは全比較履歴から最尤推定（MMアルゴリズム）で強さを同時計算するため、**比較順序に依存せず、A > B > C > A のような循環（三すくみ）があっても数学的に一意な最適解に収束**します。
- **同点の扱い**: 「同等」は双方に 0.5勝・0.5敗 を加算します。
- **未比較・少サンプル対策**: 比較0回の商品や全勝商品のスコア発散を防ぐため、強さ1.0の仮想相手との擬似対戦（$lpha = 0.5$）を事前分布として組み込んでいます（MAP推定）。未比較商品のスコアは **50.0** になります。
